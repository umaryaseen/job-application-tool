### F-02 — project ordering contradicts the approved ADR policy

Affected: `profile/baseline.py::_project_key`, `compile_baseline`,
`tests/test_m1_fix.py`; ADR-017 if a different policy is proposed.

ADR-017 says unknown project starts sort before known starts, and describes
stable-ID ordering for linked claims. `_project_key` returns `(0,0,0)` for
unknown and positive years for known; both project sorts use `reverse=True`.
Consequently known starts precede unknown starts and ID ties descend. The
fixture has one linked and one standalone project and cannot detect either
within-group ordering difference.

Narrow corrective task: implement the documented unknown-first/stable-ID policy,
or obtain an explicit reasoned ADR correction before changing that policy.
Acceptance/tests: multiple linked and standalone projects with unknown, year,
month and tied starts; shuffled input arrays produce the same approved ordering
and retain all content. Unknown ends remain unknown, never inherited/ongoing.
