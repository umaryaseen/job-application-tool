### Probes and comparison with the previous logic

The new `_heading_lines` correctly treats a compact skill line such as
`Programming Languages: Alpha | Zeta` as a non-heading. A missing, duplicated,
non-whole-line, merged, split, or out-of-order visible heading fails
`standard_headings` and, where block contents are affected,
`entry_claim_sequence`. Leading/trailing whitespace is accepted because each
line is passed through the reviewed normalizer; CRLF and form-feed page breaks
are handled by `splitlines()`. A soft hyphen at or across a heading boundary is
not accepted as an exact heading. Entries that straddle a heading boundary or
are moved into the wrong section fail the scoped entry sequence. A hidden
Contact section with no visible headings passes when all its entries are
present; a visible Contact line is treated as unexpected text and fails
`complete_text`.

The probe compared the candidate with a direct reproduction of the previous
first-occurrence algorithm. The compact skill-label case changes from
`entry_claim_sequence=False` to `True`, which is the intended correction.
Missing, duplicate, split and merged cases that could still report a heading
under first-occurrence logic now fail the whole-line check. Wrong-section and
boundary-straddling cases fail both implementations' sequence check.

One blocking case remains. With an oracle requiring hidden Contact, Skills with
one entry `Alpha`, and Languages with one entry `German (A1-A2)`, the extracted
text below contains no real Languages heading; the line `Languages` is only a
body line at that position:

```text
Synthetic Example
Skills
Alpha
Languages
German (A1-A2)
```

The candidate returns `complete_text=True`, `standard_headings=True`, and
`entry_claim_sequence=True`. The previous first-occurrence implementation
returns the same three passes. Thus the new whole-line/unique/order rule still
cannot distinguish a body line that happens to equal the missing label from the
actual heading. This directly contradicts task item 5's acceptance statement
that a missing `Languages` heading cannot pass. The focused tests cover a
missing heading, but not this body-line collision.

The hidden-Contact probe results were: hidden-only present = all content,
headings, sequence and field checks pass; hidden-only with a visible Contact
line = `complete_text` fails; hidden-only with a missing entry = sequence fails.

### Probes and assessment

The pypdf adversarial fixture is independent of the renderer. Unsandboxed
Poppler extraction confirmed that the control and `heading_body_size` PDFs have
identical text and all six text checks pass. The control has heading word boxes
of about 14.8 pt against a 10.18 pt body median (ratio 1.455) and passes
`heading_presentation`; changing both headings to body size makes the check fail.
This closes the specific round-2 body-sized-label reproduction. The earlier
renamed-heading mutation still fails the text-level heading and content checks.

The synthetic geometry cases also confirm the intended basic behavior. A normal
18.1 pt/12.9 pt document passes; a body-sized missing label, split label,
merged label, duplicate heading, and misordered heading fail; a two-page ordered
case passes; an empty or headings-only input fails; and a zero-height heading
fails. Hidden Contact plus one visible section passes when the hidden contact
words provide a normal body median. Malformed XML and a missing attribute fail
closed through `run_pdf_qa`.

The global median has a sparse-document failure. With two legitimate visible
sections each containing one body line, word heights `[18.1, 12.9, 18.1,
12.9]` give a median of 15.5 pt, so the 18.1 pt headings do not reach the
required 18.6 pt threshold. A valid one-section/one-entry document has the
same failure. `ExpectedDocument` permits both shapes, and the task explicitly
asks that one-section and hidden-Contact output be considered. This is a
mandatory-QA false negative even though the template's ordinary ratio is
healthy.

A heading-sized non-heading line remains indistinguishable from a real heading
under the new signal. In a sanitized oracle with `Skills` followed by an
`Alpha beta gamma delta` entry and `Languages` followed by a `German one two
three four` entry, the real `Languages` heading was removed and the body line
was set to 18.1 pt. `_text_checks` returned `complete_text`,
`standard_headings`, `entry_claim_sequence`, `critical_fields`, `unicode`, and
`quantitative_punctuation` all true, while `heading_presentation` also returned
true. A large name line with the same label has the same geometric ambiguity.
A 180-degree rotated heading can also pass `heading_presentation` because
`-bbox-layout` supplies no orientation signal; in the generated rotation probe,
Poppler's text order still made the overall text checks fail, so this was not an
end-to-end pass. Split/merged labels and multi-page order were rejected or
accepted as intended.

Zero-height boxes are not fail-closed in the helper. Two zero-height body words
make the median 9.05 pt and `heading_presentation` returns true, even though
those boxes are invalid. With enough zero-height words the median is zero and
the ratio calculation raises `ZeroDivisionError`. `run_pdf_qa` catches
`ET.ParseError`, `KeyError`, and `ValueError` around this call, but not
`ZeroDivisionError`, so a malformed bbox can abort QA without writing a report.
The separate `text_geometry` check would reject non-positive boxes when it can
complete, but it does not prevent this presentation-check crash.

### Architecture, security and acceptance assessment

The new check is deterministic, offline, mandatory in `run_pdf_qa`, and uses a
separate Poppler geometry signal as intended. The body-sized adversarial fixture
is a real pypdf PDF and does not weaken the earlier renamed-heading negative.
Text-level section scoping remains separate from presentation, and malformed
XML/missing attributes fail closed through the report path. No new claims,
provenance bindings, approval paths, dependencies, network access, template
injection, or personal data were introduced.

F-01 and F-02 are blocking correctness issues: one can crash QA on malformed
bbox data and the other rejects valid small documents. F-03 is a bounded
follow-up limitation, but it should be addressed or explicitly constrained in
the task/QA contract before treating the presentation signal as a complete
heading-identity proof. Fix the blocking findings, add regressions for sparse and
zero/non-finite geometry, rerun the focused command and hosted renderer suite,
and return the new runtime head for independent review.
