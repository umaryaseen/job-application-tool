### Probes and comparison with the previous logic

The new `_heading_lines` correctly treats a compact skill line such as
`Programming Languages: Alpha | Zeta` as a non-heading. A missing, duplicated,
non-whole-line, merged, split, or out-of-order visible heading fails
`standard_headings` and, where block contents are affected,
`entry_claim_sequence`. Leading/trailing whitespace is accepted because each
line is passed through the reviewed normalizer; CRLF and form-feed page breaks
are handled by `splitlines()`. A soft hyphen at or across a heading boundary is
not accepted as an exact heading. Entries that straddle a heading boundary or
are moved into the wrong section fail the scoped entry sequence. A hidden
Contact section with no visible headings passes when all its entries are
present; a visible Contact line is treated as unexpected text and fails
`complete_text`.

The probe compared the candidate with a direct reproduction of the previous
first-occurrence algorithm. The compact skill-label case changes from
`entry_claim_sequence=False` to `True`, which is the intended correction.
Missing, duplicate, split and merged cases that could still report a heading
under first-occurrence logic now fail the whole-line check. Wrong-section and
boundary-straddling cases fail both implementations' sequence check.

One blocking case remains. With an oracle requiring hidden Contact, Skills with
one entry `Alpha`, and Languages with one entry `German (A1-A2)`, the extracted
text below contains no real Languages heading; the line `Languages` is only a
body line at that position:

```text
Synthetic Example
Skills
Alpha
Languages
German (A1-A2)
```

The candidate returns `complete_text=True`, `standard_headings=True`, and
`entry_claim_sequence=True`. The previous first-occurrence implementation
returns the same three passes. Thus the new whole-line/unique/order rule still
cannot distinguish a body line that happens to equal the missing label from the
actual heading. This directly contradicts task item 5's acceptance statement
that a missing `Languages` heading cannot pass. The focused tests cover a
missing heading, but not this body-line collision.

The hidden-Contact probe results were: hidden-only present = all content,
headings, sequence and field checks pass; hidden-only with a visible Contact
line = `complete_text` fails; hidden-only with a missing entry = sequence fails.
