# M1-FIX-009: Compact contact block, unbroken skill items, kept-together entries

- Base: main after PR #11 (`deee9aa`).
- Branch: `task/009-m1-fix-009-compact-contacts`.
- Trigger: applicant review of the merged-code baseline candidate asked for a
  compact contact block (to keep a project description whole on page 1),
  skill lines that never start with "|" and keep short multiword skills
  together, and language lines with the applicant's stated qualifiers, without
  smaller type or narrower margins.

## Scope and acceptance

1. **Contacts.** Location, phone and email values (in that kind order, plan
   order within a kind) form one line separated by " | ", without per-field
   labels; each URL stays on its own labelled line ("LinkedIn:"/"Url:"), so
   URLs remain indivisible and the contact-URL width guard still applies. Plan
   text is unchanged; this is display only.
2. **Item lines.** Skill groups and contact lines carry their items. The PDF
   renders each item with its trailing " |" as one unbreakable box (the bold
   group lead is one box), so wrapping happens only between items: no line
   starts with "|", and no item is split. Extracted text is unchanged
   (`<lead>: a | b | c`). The sandboxed worker accepts a skill-group token only
   with exactly `text`, `style`, an allowlisted `lead` and non-empty `items`
   whose join equals the text, and the header-contacts token only with `lines`
   whose join equals the text. An item wider than the line fails before
   publication (`ITEM_WIDTH_ERROR`), never clipped. An item with no visible
   text, any control, line- or paragraph-separator character (CR, LF, tab,
   U+0085, U+2028, U+2029 …) or a leading "|" (after invisible characters)
   also fails before publication (`ITEM_CONTENT_ERROR`), in the parent and
   again in the worker (review round 1, F-01/F-02).
6. **Placeholder substitution** happens in one pass over the generated Typst,
   so candidate text that spells a placeholder name stays literal text; every
   placeholder must be used and no unknown placeholder may remain (review
   round 1, F-03).
3. **Kept-together entries.** Employment headers and their date lines are
   sticky blocks: a header never ends a page without its dates, and dates
   never end a page without the entry's next line.
4. **Languages** display as `<language>: <detail>` (for example
   `German: CEFR B2`); assessment semantics are unchanged.
5. Template identity `baseline-v7-m1-fix009-compact-contacts`. No font size,
   margin, spacing, selection or provenance change.

Fixtures and tests that pinned the labelled contact lines, the
`Language (detail)` format, the old token shape or the v6 identity are updated
to the new display; they are intentional presentation changes.

## Verification

`tests/test_m1_fix009.py`: contact order and kinds; header token lines; the
item-box expression and its escaping; an exact token-shape matrix; real PDFs
in which grouped skills wrap at many positions with no line starting with "|"
and every multiword item whole (both fail with the previous renderer: 15 split
items, and two separator-led lines in the single-word layout); compact contact
extraction; an over-width item failing before publication; and four layouts
that left a header or its dates alone at a page foot with the previous
rendering; the item-content matrix and build failures for a leading "|",
U+2028 and U+0085 values; and skills spelled like placeholders rendering
literally (fails with the round-1 renderer). Full suite, Ruff, format, mypy.
