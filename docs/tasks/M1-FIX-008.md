# M1-FIX-008: LinkedIn contact label and compact skill groups

- Base: main after PR #8 (`01f3a40`).
- Branch: `task/009-m1-fix-008-display-labels`.
- Trigger: applicant review of the corrected private baseline asked for a
  "LinkedIn" contact label, two further skill display groups, and a two-page
  result without smaller type, narrower margins or removing more experience.
  With separate heading lines the new groups pushed the document to three pages
  and stranded a heading at a page foot, so the applicant's fallback applies:
  more compact skill-group formatting through reviewed template work.

## Scope and acceptance

1. **Contact label.** A URL contact whose parsed host (`urlsplit().hostname`)
   is `linkedin.com` or ends with `.linkedin.com` is labelled `LinkedIn:`;
   every other URL keeps `Url:`, including lookalike hosts, user-info tricks,
   a trailing-dot host and authorities `urlsplit` rejects. One function
   (`contact_label`) feeds the plan line text, the display line and the
   renderer, and the contact-URL width guard measures every URL label
   (`URL_CONTACT_LABELS`), so an over-width LinkedIn URL still fails before
   publication. The label is static, non-claim text derived from the approved
   value; the URL itself is unchanged.
2. **Skill groups.** Two internal categories gain static display headings:
   `Programming languages` → "Programming Languages" (first) and
   `Quality & development` → "Quality & Development" (last). Internal
   identifiers in facts and plans are unchanged; unknown categories stay
   ungrouped after the groups, as before.
3. **Compact groups.** Each group is one line, `<heading>: <skills>`, with the
   heading in bold in the PDF and the identical text in TXT. The display line
   carries the heading as `lead`; the sandboxed worker accepts a skill-group
   token only if `lead` is an allowlisted heading and the text starts with
   `lead + ": "`, and every other token must have exactly `text` and `style`.
   Compound tokens in skill-group lines are width-checked in bold (the wider,
   conservative measure).
4. Template identity changes to `baseline-v6-m1-fix008-display-labels`. No
   font size, margin, spacing, selection or provenance change.
5. **QA heading detection** (added after the first review request). PDF QA
   located each section heading by the first occurrence of its label in the
   normalized text, so the new "Programming Languages:" group cut the Skills
   section at its own heading, and the heading check would also have passed if
   the real "Languages" heading were missing. A visible heading now counts only
   as a whole extracted line equal to its label, occurring exactly once and
   after the previous heading; each section's entries are searched only between
   its heading line and the next. Absent, ambiguous or misordered headings fail.

Existing fixtures and tests that pinned the two-line heading layout or the v5
identity are updated to the compact line (same skills, qualifiers and order);
they are intentional presentation changes, not loosened checks.

misordered, entry outside its section), four of which fail on the previous QA
code. Full suite, Ruff, format, mypy.
