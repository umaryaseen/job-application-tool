# M1-FIX-001: Preserve supported responsibilities and projects end to end

- Milestone: M1 corrective task
- State: IMPLEMENTED — AWAITING INDEPENDENT REVIEW
- Base: `273cdd484081948bfbedca1ff37e390b27dbd5af`
- Branch: `task/009-m1-fix-001`
- Scope: synthetic profile → validated document plan → text/PDF → QA → snapshot/export

## Problem

The native profile has employment facts with an unstructured description, but
the baseline compiler emits only title, employer and dates. It has no typed
responsibility or project records, and `DocumentPlan` has no project or
responsibility claim representation. The PDF adapter and snapshot path can
therefore validate and preserve only the flattened employment lines. The
compiler also accepts no project/support-capture records, while the production
renderer validates without forwarding captures. Existing fixtures cover
employment lines and support integrity separately, so they did not expose this
end-to-end omission.

## Proposed correction

Add bounded, revisioned responsibility and project records to the profile
schema. Responsibilities bind to an exact revision-bound employment `FactRef`
and projects carry an optional exact employment `FactRef`; subject, record kind,
employment/project scope and approved status are validated, even for records
belonging to the same person. Project names, roles, technologies, descriptions
and dates are bound typed fields or exact approved wording claims; entity names
alone are never rendered. Extend the document plan and compiler to carry these
claims in the experience section without creating a second employment entry,
with deterministic ties and explicit unknown dates. Thread one supplied
support-capture map through every validation boundary used by compilation,
text/PDF rendering, CLI, QA and snapshot build/export, failing closed when a
required capture is missing or changed. Preserve all existing stale/tampered,
wrong-scope and missing-support failures.

This is a material schema amendment. ADR-017 was independently re-reviewed as
APPROVED WITH FOLLOW-UP at `004aeda`; the implementation below remains subject
to a separate implementation review.

## Acceptance and non-goals

Synthetic end-to-end coverage must include one employment with responsibility
bullets, a linked client project, an open-source contribution, a project with
unknown dates and documentary evidence requiring an immutable capture. The real
CLI path must reach both PDF extractors, QA and snapshot/export, with negative
cases for missing/mutated captures and wrong-subject bindings. Applicant data
remains outside the repository. This task does not add new renderers, matching,
submission, or TASK-010 work.
