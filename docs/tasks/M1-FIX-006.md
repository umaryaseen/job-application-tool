# M1-FIX-006: Expected degree completion, specialization and skill display headings

- Base: main after PR #5 (`ee590699`).
- Branch: `task/009-m1-fix-006`.
- Trigger: applicant content decisions for the pending baseline content
  revision (2026-11-15). The decisions themselves stay private.

## Scope and acceptance

1. `EducationFact` gains optional `expected_completion_date` and
   `specialization`. An expected date is valid only for an ongoing degree; an
   ongoing degree must not carry an actual `completion_date` (that would claim
   an award); an expected date may not precede a known start.
2. Empty new fields are stripped from canonical fact payloads, as already done
   for earlier presentation fields, so every existing approval and binding
   digest is unchanged.
3. Presentation renders an ongoing degree with an expected date as
   `Start – Expected <Month Year>` (no "ongoing", no completion wording) and a
   specialization as its own line. Degrees without these fields render exactly
   as before. Plan claim text includes both values so validated plans cover
   every visible claim.
4. Skill groups keep their internal category identifiers in facts and plans;
   only the static display headings change, in this order: AI & Machine
   Learning, Data Engineering & Analytics, Backend & Databases, Frontend &
   Visualization, Cloud & Infrastructure. Unknown categories stay ungrouped.
5. Template identity changes, so earlier artifact approvals cannot be reused
   for new bytes.

## Non-goals

No new skill categories, no change to which facts are selected, no automatic
data migration and no applicant data in tests. Personal profile, receipts and
artifacts remain outside Git.

## Verification

Synthetic model, digest-stability, presentation, plan-validation and real
renderer extraction tests; full suite, Ruff, format, mypy. Independent review
before any personal baseline uses this code.
