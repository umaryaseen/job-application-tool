# ADR-001: Canonical schema and JSON Resume

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 §Data model, 509–560; R2 270–317; R3 387, 1061–1671.

## Alternatives

JSON Resume plus extension fields; custom internal model with adapter; renderer-owned YAML as database.

## Recommendation / decision

Use a custom versioned JSON/Pydantic model with explicit facts, evidence, reviewed support bindings and approved wording variants. JSON Resume becomes a later import/export adapter, never the provenance authority.

## Trade-offs and consequences

A standard-only model is portable but cannot express the required support graph cleanly. A custom model adds validation/migration work while keeping facts independent of document format. Renderer YAML is convenient but loses evidence and would couple data to layout.

## Validation and adoption gate

TASK-002 exports schema; TASK-003 validates the graph. JSON Resume import later creates unverified drafts and a loss report; export discloses dropped provenance/localized fields. Do not claim lossless round trips.

## Reconsideration

Revisit when an interchange consumer demonstrates a concrete need. Exact external schema version is chosen and pinned in TASK-030.
