# ADR-007: Requirement extraction

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 562–596, 1397; R2 392–446; R3 541–571.

## Alternatives

Rules only; structured LLM extraction; hybrid model-first extraction.

## Recommendation / decision

Use deterministic source-span extraction, explicit English/German priority cues, numeric/language constraints and ALL/ANY groups. Preserve unknown/unspecified and needs_review. A later LLM may propose additional requirements; it never overrides reviewed source spans.

## Trade-offs and consequences

Rules are transparent and offline but miss nuanced prose. Model proposals can recover nuance but can add requirements or follow malicious instructions. Strict schema and quoted offsets constrain output but do not prove that the classification is correct; user review remains required.

## Validation and adoption gate

TASK-011/012/014 cover bilingual cues, negation, alternatives and ambiguous sections. Invalid spans/quotes fail. Degree-or-equivalent is one alternative group; a preferred requirement must not become mandatory. No JD text becomes a career fact.

## Reconsideration

Revisit using a frozen labeled corpus and documented errors. Add spaCy only if measured extraction complexity warrants its runtime.
