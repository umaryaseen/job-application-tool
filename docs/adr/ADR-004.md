# ADR-004: PDF renderer selection

- Date: 2026-09-08
- Status: **PROPOSED / SPIKE REQUIRED**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 851 recommends RenderCV; R3 430, 703–707 recommends HTML/CSS + Playwright; R2 470–495 is format-focused.

## Alternatives

RenderCV/Typst adapter; Jinja2 HTML/CSS + Playwright Chromium; direct PDF library; DOCX-to-PDF conversion.

## Recommendation / decision

Recommend RenderCV for the initial Python-only profile-to-CV workflow, subject to TASK-005. Run a small same-content EN/DE and hostile-input comparison against HTML/Playwright. Adopt exactly one backend after independent review.

## Trade-offs and consequences

RenderCV provides resume-specific schema/design controls but its default theme may use alignment/icons that violate our rules and custom theme APIs can change. HTML is familiar and useful for later previews, but installs Chromium and requires print/font/network hardening. Direct PDF code adds layout work. DOCX conversion introduces another layout engine and is deferred.

## Validation and adoption gate

Use the same 1-page and 2-page synthetic document plans, long names, German Unicode, wrapping and malicious markup. Record actual install/runtime versions, pages, extraction/order, local asset handling and visual review. Both candidates must escape data, deny arbitrary includes/network, and preserve exact text. Demonstrate a minimal synthetic one-page letter path for the recommended backend or record an explicit reconsideration gate before TASK-022, which must not silently add a second backend. If neither passes, mark CHANGES REQUIRED; no silent fallback or pre-approved winner. TASK-006 depends on accepted spike.

## Reconsideration

Revisit if the chosen version cannot meet layout/security tests without a large fork. Pin exact resolved versions/fonts only after running the spike. Primary docs: https://docs.rendercv.com/ and https://playwright.dev/python/docs/api/class-page#page-pdf.

## TASK-005 experiment findings (2026-09-12)

TASK-005 ran on macOS 13.6.9 x86_64 with Python 3.12.14. RenderCV 2.8,
Typst 0.15.0, rendercv-fonts 0.5.1, Playwright 1.62.0 and pypdf 6.18.1 are
locked under `experiments/renderer/uv.lock`; Poppler 25.08.0 supplied
`pdftotext` and `pdftoppm`. The complete synthetic plans rendered through
RenderCV/Typst using local bundled fonts, 11pt body text, 20mm margins and A4
pages. Short, Unicode, wrapping and hostile fixtures were one page; the
bounded long fixture was two pages; the synthetic letter was one page. Poppler
and pypdf recovered the claim prefixes in order, and raster inspection found
no clipping or missing glyphs. A sandboxed local HTTP probe was denied and
hostile scalar text remained literal after a token-to-Typst-string boundary.

Playwright installed as a Python package, but its current Chromium installer
returned `ERROR: Playwright does not support chromium on mac13`; no browser
PDF, raster, or browser-side resource check was observed. The HTML adapter
still escapes text and installs a request-abort route, but this candidate is
not measured on this laptop.

The proposed experiment outcome is RenderCV/Typst, conditional on independent
review. The adapter must retain local package/font pinning, escaped scalar
insertion and an OS/process security policy. This does not change the ADR
status: the backend is not accepted until an independent review and the
supervising engineer's decision. If the boundary is rejected, reconsider ADR-
004 before TASK-022 rather than silently adding a second backend. See
`docs/experiments/RENDERER_DECISION.md` for commands, hashes, visual findings
and limitations.

## TASK-005 corrective qualification (2026-09-12; awaiting independent review)

The F-001 correction replaces prefix checks with a complete ordered-content
oracle for both Poppler and pypdf. It normalizes only NFC, extractor soft
hyphens (including digit date hyphens), an extractor-split `http://` or
`https://` scheme, and whitespace introduced by visual wrapping. Punctuation,
numbers, units, negation and qualifiers remain meaningful. The old failures
were extractor artifacts: RenderCV/Typst contained the full text, while
Poppler/pypdf represented soft hyphens and the URL boundary differently. All
five CV fixtures and the synthetic letter now match complete content in both
extractors; suffix, qualification, duplication, reordering and unexpected
content controls are rejected. Any complete-content mismatch makes the
candidate unsuccessful even when PDF generation succeeds.

The F-002 qualification narrows the proposed outcome to a feasible backend for
this laptop. Playwright 1.62.0's Python package installed, but Chromium setup
failed on macOS 13.6.9 x86_64 with `ERROR: Playwright does not support
chromium on mac13`. HTML/Playwright layout, extraction, raster and browser
security behavior remain untested. No unsupported workaround or comparative
quality claim is made. Reconsider when a supported target environment is
available, RenderCV fails a mandatory content/Unicode/visual/security gate, or
its adapter maintenance becomes excessive. Until independent review and the
supervising engineer's decision, ADR-004 remains PROPOSED / SPIKE REQUIRED;
if RenderCV fails, no backend is recommended and TASK-006 remains blocked.
