# ADR-004: PDF renderer selection

- Date: 2026-09-08
- Status: **PROPOSED / SPIKE REQUIRED**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 851 recommends RenderCV; R3 430, 703–707 recommends HTML/CSS + Playwright; R2 470–495 is format-focused.

## Alternatives

RenderCV/Typst adapter; Jinja2 HTML/CSS + Playwright Chromium; direct PDF library; DOCX-to-PDF conversion.

## Recommendation / decision

Recommend RenderCV for the initial Python-only profile-to-CV workflow, subject to TASK-005. Run a small same-content EN/DE and hostile-input comparison against HTML/Playwright. Adopt exactly one backend after independent review.

## Trade-offs and consequences

RenderCV provides resume-specific schema/design controls but its default theme may use alignment/icons that violate our rules and custom theme APIs can change. HTML is familiar and useful for later previews, but installs Chromium and requires print/font/network hardening. Direct PDF code adds layout work. DOCX conversion introduces another layout engine and is deferred.

## Validation and adoption gate

Use the same 1-page and 2-page synthetic document plans, long names, German Unicode, wrapping and malicious markup. Record actual install/runtime versions, pages, extraction/order, local asset handling and visual review. Both candidates must escape data, deny arbitrary includes/network, and preserve exact text. If neither passes, mark CHANGES REQUIRED; no silent fallback or pre-approved winner. TASK-006 depends on accepted spike.

## Reconsideration

Revisit if the chosen version cannot meet layout/security tests without a large fork. Pin exact resolved versions/fonts only after running the spike. Primary docs: https://docs.rendercv.com/ and https://playwright.dev/python/docs/api/class-page#page-pdf.
