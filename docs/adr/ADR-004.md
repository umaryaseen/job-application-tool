# ADR-004: PDF renderer selection

- Date: 2026-09-08
- Status: **ACCEPTED — CURRENT LAPTOP ONLY (2026-09-13 amendment)**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 851 recommends RenderCV; R3 430, 703–707 recommends HTML/CSS + Playwright; R2 470–495 is format-focused.

## Alternatives

RenderCV/Typst adapter; Jinja2 HTML/CSS + Playwright Chromium; direct PDF library; DOCX-to-PDF conversion.

## Recommendation / decision

Adopt RenderCV/Typst for the current macOS 13.6.9 x86_64 laptop under the reviewed 2026-09-13 amendment below. The original same-content two-engine comparison remains incomplete; HTML/Playwright is BLOCKED/UNTESTED. Exactly one production adapter may be implemented. No comparative superiority or support on other platforms is asserted.

## Trade-offs and consequences

RenderCV provides resume-specific schema/design controls but its default theme may use alignment/icons that violate our rules and custom theme APIs can change. HTML is familiar and useful for later previews, but installs Chromium and requires print/font/network hardening. Direct PDF code adds layout work. DOCX conversion introduces another layout engine and is deferred.

## Validation and adoption gate

Use the same 1-page and 2-page synthetic document plans, long names, German Unicode, wrapping and malicious markup. Record actual install/runtime versions, pages, extraction/order, local asset handling and visual review. Any adopted candidate must escape data, deny arbitrary includes/network, and preserve exact text. The 2026-09-13 amendment removes successful execution of the alternative candidate as an adoption prerequisite; it does not relax these requirements for RenderCV. Demonstrate a minimal synthetic one-page letter path for the recommended backend or record an explicit reconsideration gate before TASK-022, which must not silently add a second backend. If neither passes, mark CHANGES REQUIRED; no silent fallback or pre-approved winner. TASK-006 depends on accepted spike.

## Reconsideration

Revisit if the chosen version cannot meet layout/security tests without a large fork. Pin exact resolved versions/fonts only after running the spike. Primary docs: https://docs.rendercv.com/ and https://playwright.dev/python/docs/api/class-page#page-pdf.

## TASK-005 experiment findings (2026-09-12)

TASK-005 ran on macOS 13.6.9 x86_64 with Python 3.12.14. RenderCV 2.8,
Typst 0.15.0, rendercv-fonts 0.5.1, Playwright 1.62.0 and pypdf 6.18.1 are
locked under `experiments/renderer/uv.lock`; Poppler 25.08.0 supplied
`pdftotext` and `pdftoppm`. The complete synthetic plans rendered through
RenderCV/Typst using local bundled fonts, 11pt body text, 20mm margins and A4
pages. Short, Unicode, wrapping and hostile fixtures were one page; the
bounded long fixture was two pages; the synthetic letter was one page. Poppler
and pypdf recovered the claim prefixes in order, and raster inspection found
no clipping or missing glyphs. A sandboxed local HTTP probe was denied and
hostile scalar text remained literal after a token-to-Typst-string boundary.

Playwright installed as a Python package, but its current Chromium installer
returned `ERROR: Playwright does not support chromium on mac13`; no browser
PDF, raster, or browser-side resource check was observed. The HTML adapter
still escapes text and installs a request-abort route, but this candidate is
not measured on this laptop.

The proposed experiment outcome is RenderCV/Typst, conditional on independent
review. The adapter must retain local package/font pinning, escaped scalar
insertion and an OS/process security policy. This does not change the ADR
status: the backend is not accepted until an independent review and the
supervising engineer's decision. If the boundary is rejected, reconsider ADR-
004 before TASK-022 rather than silently adding a second backend. See
`docs/experiments/RENDERER_DECISION.md` for commands, hashes, visual findings
and limitations.

## TASK-005 corrective qualification (2026-09-12; awaiting independent review)

The F-001 correction replaces prefix checks with a complete ordered-content
oracle for both Poppler and pypdf. It normalizes only NFC, extractor soft
hyphens (including digit date hyphens), an extractor-split `http://` or
`https://` scheme, and whitespace introduced by visual wrapping. Punctuation,
numbers, units, negation and qualifiers remain meaningful. The old failures
were extractor artifacts: RenderCV/Typst contained the full text, while
Poppler/pypdf represented soft hyphens and the URL boundary differently. All
five CV fixtures and the synthetic letter now match complete content in both
extractors; suffix, qualification, duplication, reordering and unexpected
content controls are rejected. Any complete-content mismatch makes the
candidate unsuccessful even when PDF generation succeeds.

The F-002 qualification narrows the proposed outcome to a feasible backend for
this laptop. Playwright 1.62.0's Python package installed, but Chromium setup
failed on macOS 13.6.9 x86_64 with `ERROR: Playwright does not support
chromium on mac13`. HTML/Playwright layout, extraction, raster and browser
security behavior remain untested. No unsupported workaround or comparative
quality claim is made. Reconsider when a supported target environment is
available, RenderCV fails a mandatory content/Unicode/visual/security gate, or
its adapter maintenance becomes excessive. Until independent review and the
supervising engineer's decision, ADR-004 remains PROPOSED / SPIKE REQUIRED;
if RenderCV fails, no backend is recommended and TASK-006 remains blocked.


## Accepted architecture amendment — 2026-09-13

The supervising engineer proposed adoption on independently reviewed current-laptop
requirements, with Playwright retained as a reconsideration option. Codex, acting
as the independent reviewer of that proposal, accepts it; see the dated addendum
in [TASK-005 review](../reviews/TASK-005.md). This explicitly changes TASK-005's
original requirement to render both engines before choosing a backend. Earlier
proposals and the incomplete comparison above remain historical evidence.

Rationale: R1 844–859 recommends a Python pipeline with RenderCV; R3 695–707
recommends HTML/CSS/Playwright. Neither establishes that both must run before a
single local backend can be adopted. R2 470–495 instead requires extraction,
reading order, fields, duplication, geometry and visual checks, including multiple
parsers. Two independent parsers are still required; two production rendering
engines are not. ADR-013 specifies output geometry/readability and ADR-015
requires local isolation. The mandatory acceptance matrix tests these properties,
not RenderCV's superiority over Chromium.

The prior independent review of `62eddb346995c8ef7ade694d45775779f5017c36`
records complete Poppler/pypdf matches, mutation controls, A4 one/two-page CVs,
a one-page letter, and synthetic Unicode/hostile-input results. These are bounded
spike results, not approval of an unbuilt production adapter. No concrete unmet
RenderCV requirement is resolved merely by running Chromium elsewhere. Such a
run could reveal an easier adapter or better layout, but would not prove the
RenderCV process policy or this laptop's compatibility. Deferring it accepts
uncertainty about relative quality and maintenance cost, not a known safety
failure.

**TASK-006 is READY for implementation on the current laptop.** No supported-browser
comparison is required beforehand. Normal integration of the reviewed branch into
main remains a Git prerequisite; this amendment neither merges nor starts work.
TASK-006 must validate its actual process isolation, literal-text boundary, pinned
engine/fonts/templates, private staging, timeouts and cleanup; TASK-007 must pass
its full extraction/critical-field/order/geometry/Unicode corpus. A failed selected-
backend requirement blocks that adapter's approval and triggers reconsideration;
a blocked alternate engine cannot excuse it. The experiment's informal filesystem
policy and letter post-processing route are not blanket production approvals.

Playwright remains **BLOCKED/UNTESTED**. Preserve the historical runner result
`experiment_status=blocked`, exit **2** (incomplete comparison); exit **1** denotes
measured failure, and exit **0** denotes the complete experiment. Do not change
these semantics or relabel exit 2 a full pass. This amendment changes the adoption
rule, not the observed result.

Reconsideration owner: supervising engineer. Triggers: target OS/architecture or
runtime changes, failure of a mandatory RenderCV requirement, or excessive adapter
maintenance (including the literal insertion or letter route). On a changed target,
rerun selected-backend locked setup and real fixture/extraction/raster/security tests
before claiming support; this is mandatory environment validation. At a trigger,
evaluate whether to run the same-content Playwright comparison on an officially
supported environment using the recorded short, two-page, Unicode, wrapping and
hostile plans, both extractors and raster/resource checks. No unsupported browser
installation or laptop OS change is required by this decision.
