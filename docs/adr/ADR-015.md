# ADR-015: Local security and rendering isolation

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 1066–1163; R2 561–603; R3 774–847.

## Alternatives

Always-connected web app; offline single process; container/service isolation from day one.

## Recommendation / decision

Offline local execution with private external data root, bounded input, trusted templates/fonts, escaped text, no renderer network or arbitrary includes, no telemetry, and sanitized logs. No Docker requirement. API credentials and identity documents never enter prompts/Git/CI.

## Trade-offs and consequences

Local-first removes many hosted risks but does not encrypt disks or stop compromised dependencies. Containers add cost and are not a substitute for correct input handling. Avoiding fetch/upload features prevents SSRF/parser attack surfaces in the MVP.

## Validation and adoption gate

TASK-001 guardrails precede any personal data; TASK-006/007 renderer hostile-input/resource tests; TASK-019 full MVP security regression. Use full-disk protection/secure backups supplied by the OS; report plaintext storage honestly. Verify model/provider egress in later tasks.

## Reconsideration

Reassess before URL ingestion, web UI, browser credentials or multi-user hosting. This is a security design, not a claim of GDPR compliance.
