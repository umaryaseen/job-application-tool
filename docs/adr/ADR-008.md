# ADR-008: Application LLM providers and location

- Date: 2026-09-08
- Status: **DEFERRED — OFF BY DEFAULT**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 735–762, 856–869, 1066–1123; R2 571–579; R3 697–701, 802–847.

## Alternatives

No model; local model; opt-in cloud model; single-vendor architecture.

## Recommendation / decision

M1–M4 require no LLM. Introduce narrow provider interfaces only in TASK-028, then an explicitly selected local or cloud adapter in TASK-031. Default disabled. Wording proposals require human semantic review before export.

## Trade-offs and consequences

Local models avoid remote disclosure but require hardware and downloads and can still fabricate. Cloud models simplify setup and can improve writing but require provider/retention/budget decisions. No vendor is selected here; a universal provider framework would be premature.

## Validation and adoption gate

Strict JSON proposal schemas, timeouts, maximum output sizes, no tools, no arbitrary URLs, safe logs, no infinite retry loop, and no silent fallback. Cloud opt-in discloses only the selected minimal professional evidence; contact data stays local. Record exact provider/model/config/prompt and source-bundle hashes.

## Reconsideration

Choose after applicant data-disclosure preference and laptop capability are known. Both choices must pass the same factuality and injection tests; an API outage cannot break deterministic builds.
