# ADR-010: Reuse and licensing boundaries

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 807–842; R2 529–559; R3 363–435, 1920–1930.

## Alternatives

Fork Resume Matcher; reuse selected components; build small domain core and use projects as references.

## Recommendation / decision

Own the small evidence/provenance domain. Study Resume Matcher workflows and OpenResume parser behavior; do not fork either, vendor AGPL/GPL code, or add their full stacks. Use mature focused libraries only when they materially reduce work.

## Trade-offs and consequences

A fork accelerates UI breadth but couples input/data/control flow to another product. Bounded reuse is useful after interface and license inspection. OpenResume AGPL and pyresparser GPL are not casual copy sources; separate process execution is not asserted to eliminate license obligations.

## Validation and adoption gate

Record dependency purpose, exact version, license source, introducing task and transitive concerns. TASK-034 evaluates an optional parser without copying code and records distribution implications. No LICENSE is assigned to original private work without owner choice; R3 Apache-2.0 is a recommendation, not authorization to publish.

## Reconsideration

Reconsider a component only after a concrete savings/maintenance comparison. Current project/license declarations checked at https://github.com/srbhr/Resume-Matcher and https://github.com/xitanggg/open-resume; not a legal compatibility opinion.
