# ADR-003: CLI before a web interface

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 844–854, 971–1008; R3 648–724.

## Alternatives

CLI; local web UI plus API; full-stack UI-first fork.

## Recommendation / decision

Start with argparse CLI and a Python package. Pure domain functions have no web dependency. Document review opens local artifacts and records explicit approval.

## Trade-offs and consequences

CLI suits agent tasks and a technical user; interactive editing is less polished. UI-first provides convenience but requires two runtimes, browser security and more contracts before the first CV. Add a UI only after measured review friction justifies it.

## Validation and adoption gate

TASK-001 establishes a CLI entry point and tests its actual error/help behavior. TASK-032 later designs a bounded localhost interface with CSRF/auth/origin controls; do not scaffold it now.

## Reconsideration

Revisit after M3 if repeated manual review is the dominant user cost.
