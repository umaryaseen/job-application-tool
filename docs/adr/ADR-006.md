# ADR-006: ESCO integration

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING — IMPLEMENTATION DEFERRED**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 593–596; R2 392–446; R3 389–414. Official API notice checked 2026-09-08 differs from the reports.

## Alternatives

Internal alias dictionary; live ESCO API; hosted local ESCO API; pinned downloaded EN/DE dataset.

## Recommendation / decision

Start with reviewed internal aliases. Later import a versioned EN/DE ESCO data snapshot as optional enrichment; keep internal IDs stable and ESCO URIs optional. No runtime ESCO service or mandatory network calls.

## Trade-offs and consequences

The taxonomy adds multilingual concepts, but a related/broader/narrower concept is not a synonym and rapidly changing technologies may need internal terms. Live services harm offline reproducibility. The official local API is currently reference-only pending replacement, making service reuse especially unattractive.

## Validation and adoption gate

TASK-026 records official dataset acquisition, version, SHA-256, attribution/reuse conditions and import schema. The official download flow may require user interaction/email; do not invent a download link or disclose email automatically. Unavailable ESCO leaves exact matching fully functional.

## Reconsideration

Revisit only for demonstrated mapping gaps. Source: https://esco.ec.europa.eu/en/use-esco/use-esco-services-api and https://esco.ec.europa.eu/en/use-esco/download. API software licensing and classification reuse are separate.
