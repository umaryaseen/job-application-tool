# ADR-005: Semantic matching approach

- Date: 2026-09-08
- Status: **DEFERRED / BENCHMARK REQUIRED**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 598–629, 813–816; R2 392–468; R3 573–624, 697–701.

## Alternatives

Exact/alias matching only; Sentence Transformers multilingual embeddings; other local encoders; cloud embeddings; LLM-only scoring.

## Recommendation / decision

Ship the exact/curated-alias matrix first. Later benchmark local Sentence Transformers with paraphrase-multilingual-MiniLM-L12-v2 as one candidate, against that baseline and a longer-context multilingual alternative if truncation/quality requires it. No vector server; exact cosine retrieval over the small evidence bank.

## Trade-offs and consequences

Local encoders reduce disclosure but add downloads, memory and semantic false positives. Cloud models add a data boundary and costs. An LLM score is harder to reproduce. Similarity is retrieval relevance, never proof of qualification or an ATS success probability.

## Validation and adoption gate

TASK-027 defines held-out EN/DE relevance labels before tuning; TASK-029 runs a pinned real model evaluation. Unit stubs are insufficient. Enforce tokenizer limits per chunk, retain chunk-to-fact provenance, record model revision/cache key and reject silent truncation. Semantic-only suggestions cannot mark mandatory criteria met.

## Reconsideration

Enable only with measured recall benefit and acceptable CPU/memory on the actual laptop. Thresholds remain unselected until benchmark. Model card: https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2.
