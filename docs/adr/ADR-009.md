# ADR-009: DOCX output

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING — IMPLEMENTATION DEFERRED**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 123–148, 959; R2 470–495; R3 703–707, 1936–1942.

## Alternatives

Generate DOCX from DocumentPlan; convert PDF to DOCX; use DOCX as canonical source; maintain independently edited DOCX.

## Recommendation / decision

Use python-docx in TASK-024 to project the same validated document plan into ordinary paragraphs, headings and bullets. No PDF-to-DOCX conversion and no DOCX source database.

## Trade-offs and consequences

Direct projection preserves fact identity and reading sequence. Pagination varies by Word/LibreOffice/fonts; do not claim the PDF page count establishes DOCX page count. Conversion can corrupt structure. A second independently edited document creates drift.

## Validation and adoption gate

Test XML/text extraction, complete critical fields, no text boxes/core tables/header contacts, Unicode and exact plan content. Render with an explicitly recorded available office engine for visual/page review; if unavailable mark DOCX layout unverified and block DOCX release.

## Reconsideration

Prioritize only after M3 or an actual portal requires DOCX. Primary library documentation: https://python-docx.readthedocs.io/en/latest/.

2026-11-11 proposed priority amendment: the user requests editable CV/letter files as part of the application pack. ADR-017 treats TASK-024 as a requested deliverable after M3; direct projection, office-render QA and existing dependencies remain unchanged. Implementation is still pending.
