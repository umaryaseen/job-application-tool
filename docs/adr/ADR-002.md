# ADR-002: Local files and SQLite

- Date: 2026-09-08
- Status: **ACCEPTED FOR PLANNING**
- Decision owner: supervising engineer; independent review recorded in `../reviews/`.

## Context and research disagreement

R1 844–869, 1010–1058; R2 497–527; R3 692–695.

## Alternatives

JSON/files only; SQLite immediately; PostgreSQL with optional SQLite mode.

## Recommendation / decision

Canonical profiles and immutable snapshots use private files first. Introduce SQLite via stdlib sqlite3 for the M4 tracker; retain files as the canonical career record. No dual backend, ORM or vector database.

## Trade-offs and consequences

Files are directly inspectable and portable. They need atomic publication and revision checks. SQLite supplies transactional tracking with no server; PostgreSQL is unnecessary for one local writer and adds installation/backup burden. SQLite is not encrypted merely because it is local.

## Validation and adoption gate

TASK-008 tests atomic snapshot publication. TASK-023 enables foreign keys, numbered migrations and transactional append-only events. TASK-033 covers backup/export consistency.

## Reconsideration

Revisit for multi-user concurrent writes or shared service requirements; do not copy a live database file onto a network share. See https://www.sqlite.org/whentouse.html.
